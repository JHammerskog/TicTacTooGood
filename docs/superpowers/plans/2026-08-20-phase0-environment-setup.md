# Phase 0: Environment Setup Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Get every Phase 0 tool installed and prove the stack works end-to-end: `docker-compose up` starts a React (Vite) frontend and a Flask backend, and the frontend displays a message it fetched from the backend.

**Architecture:** Two independent apps in one repo (`frontend/`, `backend/`), each with its own Dockerfile, wired together by one `docker-compose.yml`. The browser (not the frontend container) talks directly to the backend's published port — the two containers don't need to reach each other over the docker network for this phase.

**Tech Stack:** React (Vite, JavaScript) + Flask (uv-managed) + Docker Compose, Ruff (Python lint/format), Prettier (JS format), Bootstrap 5 (installed/importable only).

**Spec:** `docs/superpowers/specs/2026-08-20-phase0-environment-setup-design.md`

## Global Constraints

- No automated tests this phase (spec: "Out of scope for Phase 0") — deliverables are verified manually (curl, browser, `docker-compose logs`).
- Never run git commands that write state (`add`, `commit`, `branch`, `push`). Every task ends with changes left unstaged/uncommitted for the user to review and commit themselves — do not run `git add`/`git commit` even though the template below would normally end a task that way.
- Machine-level tool installs (Docker Engine, npm, uv) are **not** part of the numbered tasks below — they modify persistent system state, so they're listed as commands for the user to run themselves first. Project-scoped installs (npm packages inside `frontend/`, Python packages inside `backend/` via `uv add`) are normal implementation steps and are executed as part of the tasks.
- Frontend talks to backend via `http://localhost:5000` (the backend's published host port), not a docker-network hostname — the fetch call runs in the browser, which only sees published host ports, not container-to-container networking.

## Prerequisites (run these yourself before Task 1 — machine-level installs)

**Docker Engine + Compose plugin.** This WSL2 distro already has `systemd=true` set in `/etc/wsl.conf`, so Docker Engine can run natively here (no Docker Desktop / Windows install needed):

```bash
sudo apt-get update
sudo apt-get install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc
echo \
  "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu \
  $(. /etc/os-release && echo "$VERSION_CODENAME") stable" | \
  sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
sudo apt-get update
sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
sudo systemctl enable --now docker
sudo usermod -aG docker "$USER"
```

Then **open a new terminal** (or `wsl.exe --shutdown` from Windows and reopen) so the `docker` group membership takes effect. Verify:
```bash
docker run hello-world
docker compose version
```

**npm** (Node itself is already installed system-wide; Ubuntu splits `npm` into its own package):
```bash
sudo apt-get install -y npm
npm -v
```

**uv**:
```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
uv --version
```


- [ ] **Step 2: Write the app**

`backend/app.py`:
```python
from flask import Flask, jsonify
from flask_cors import CORS

app = Flask(__name__)
CORS(app)


@app.route("/api/hello")
def hello() -> tuple[dict[str, str], int]:
    """Return a hello-world payload proving the backend is reachable.

    Returns:
        A JSON-serializable dict with a "message" key, and HTTP 200.
    """
    return jsonify(message="Hello from Flask"), 200


if __name__ == "__main__":
    app.run(host="0.0.0.0", port=5000, debug=True)
```

- [ ] **Step 3: Verify it runs and responds**


### Task 3: Wire frontend to backend (no Docker yet)

**Files:**
- Modify: `frontend/src/App.jsx`

**Interfaces:**
- Consumes: `GET http://localhost:5000/api/hello` from Task 2, returning `{"message": string}`.
- Produces: `App.jsx` renders that message inside an `<h1>`.

- [ ] **Step 1: Replace App.jsx contents**

`frontend/src/App.jsx`:
```jsx
import { useEffect, useState } from 'react';

function App() {
  const [message, setMessage] = useState('Loading...');

  useEffect(() => {
    fetch('http://localhost:5000/api/hello')
      .then((res) => res.json())
      .then((data) => setMessage(data.message))
      .catch(() => setMessage('Could not reach backend'));
  }, []);

  return (
    <div>
      <h1>{message}</h1>
    </div>
  );
}

export default App;
```

**What this introduces (React-specific):** `useState('Loading...')` holds a value that, when changed, triggers a re-render — think of it as a variable React watches. `useEffect(fn, [])` runs `fn` once, right after the component's first render (the empty `[]` means "don't re-run this on every render, only once") — this is the client-side equivalent of a Flask route doing work before rendering a Jinja template, except here the page has already rendered once (showing "Loading...") before the real value arrives and triggers a second render in its place.

- [ ] **Step 2: Verify end-to-end, without Docker**

```bash

```
In another:
```bash

```
Visit the printed frontend URL. Expected: page shows "Hello from Flask" (briefly "Loading..." first). Stop both servers (Ctrl+C) once confirmed.

- [ ] **Step 3: Stop — do not commit**

### Task 4: Dockerize both apps and wire docker-compose

**Files:**
- Create: `frontend/Dockerfile`
- Create: `backend/Dockerfile`
- Create: `docker-compose.yml`

**Interfaces:**
- Consumes: `frontend/` from Task 1/3, `backend/` from Task 2.
- Produces: `docker-compose up` starts both services; backend published on host port `5000`, frontend on host port `5173`.

- [ ] **Step 1: Backend Dockerfile**

`backend/Dockerfile`:
```dockerfile
FROM python:3.12-slim
COPY --from=ghcr.io/astral-sh/uv:latest /uv /uvx /bin/
WORKDIR /app
COPY pyproject.toml uv.lock ./
RUN uv sync --frozen
COPY . .
CMD ["uv", "run", "flask", "--app", "app", "run", "--host=0.0.0.0", "--port=5000", "--debug"]
```

- [ ] **Step 2: Frontend Dockerfile**

`frontend/Dockerfile`:
```dockerfile
FROM node:22-slim
WORKDIR /app
COPY package.json package-lock.json ./
RUN npm install
COPY . .
CMD ["npm", "run", "dev", "--", "--host", "0.0.0.0"]
```

- [ ] **Step 3: docker-compose.yml**

`docker-compose.yml` (repo root):
```yaml
services:
  backend:
    build: ./backend
    ports:
      - "5000:5000"
    volumes:
      - ./backend:/app

  frontend:
    build: ./frontend
    ports:
      - "5173:5173"
    volumes:
      - ./frontend:/app
      - /app/node_modules
    depends_on:
      - backend
```
The `- /app/node_modules` line is an anonymous volume: it stops the host's (nonexistent, host doesn't run `npm install`) `node_modules` from overwriting the one built inside the container.

- [ ] **Step 4: Verify**

```bash
docker compose up --build
```
Expected: both containers start, logs show Vite and Flask dev servers up. Visit `http://localhost:5173` in a browser — same "Hello from Flask" result as Task 3, now fully containerized. Stop with Ctrl+C.

- [ ] **Step 5: Stop — do not commit**
